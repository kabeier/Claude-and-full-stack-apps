Live: the key goes in .env, and .env stays off GitHub

# front-end/.env  (next to package.json)
VITE_SUPABASE_URL=https://<id>.supabase.co
VITE_SUPABASE_ANON_KEY=sb_publishable_…
# .gitignore  (project root)
.env
  • Vite only shares names that start with VITE_
  • Code reads them with import.meta.env.VITE_SUPABASE_URL
  • Vite reads .env when it starts: restart npm run dev
  • Publishable key only. The secret key never goes in a VITE_ variable.

Check: git status must not list .env.

** LIVE, about 3 minutes. ** You create this file, not Claude: "Secrets are yours to handle." Use the same URL and key as in Postman (no /rest/v1).

"Why VITE_? Vite puts these values into the JavaScript it sends to every browser. The prefix is you saying 'yes, this one is OK to share'. That's why the secret key never gets the prefix."

"Why hide the publishable key if it's safe to share? Habit, and the curriculum's rule: never commit keys." Add .env to the root .gitignore, run git status: no .env in the list. Commit ("Restructure: front-end + supabase"): it's also the undo point if you need the backup later.

Anon key = publishable key: the curriculum's name for the variable comes from Supabase's older key names.
