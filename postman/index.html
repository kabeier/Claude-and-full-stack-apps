Ticked API in Postman

Send every CRUD request to Supabase's API by hand, just like in class. Build it yourself (best for learning), or import the ready-made collection at the bottom.

Build it yourselfSet up, then every request in order. About 15 minutes. Import the ready-made collectionDownload or copy the JSON, then set two variables.

Before you start

  1. Postman is installed and you're signed in. Not yet? See step 1 on the home page.
  2. Your Project URL: Supabase → Integrations → Data API → Project URL. It ends in /rest/v1/.
  3. Your publishable key: Project Settings → API Keys → Publishable key (starts sb_publishable_). Never the secret key.
  4. Using your own app? Everything below works the same. Swap users and tasks for your table names, and the bodies for your columns.

Build it yourself

1 · Make the collection

  1. Postman → New → Collection. Name it Ticked API.
  2. Click the collection, open the Variables tab, and add two rows:
    VariableValue
    base_urlYour Project URL. Keep /rest/v1, delete only the last /:
    https://your-project-id.supabase.co/rest/v1
    publishable_keyYour publishable key
  3. Click Save (top right). Easy to forget: without it, the variables are empty.

2 · The first request, with the headers

  1. Inside the collection: Add request. Name it Read users.
  2. Headers tab → Bulk Edit (right side) → paste: 
    apikey:{{publishable_key}}
Authorization:Bearer {{publishable_key}}
Content-Type:application/json
    Click Key-Value Edit to switch back. The {{publishable_key}} parts should be orange or green. Red = Postman can't find the variable: save the collection variables.
  3. Method GET, URL {{base_url}}/users → Send.

Got []? The request worked, but Row Level Security hid every row. Add the temporary dev rules (step 3 on the home page), then send again.

3 · Every next request

  1. Right-click Read users → Duplicate. The 3 headers come along. Rename it, then change the method and URL.
  2. Requests with a body: Body tab → raw → JSON, then paste the body.
  3. After each one, look at three things: the status code, the response body, and the Table Editor in Supabase (refresh it).

4 · The requests, in order

POST Create a user

URL
{{base_url}}/users
Add header
Prefer:return=representation (sends the new row back)
Body
{"name":"Demo User","email":"demo@ticked.app"}
Expect
201 + the row. Copy its id. Keep this user: your app uses it in Part II.

POST Create a task

URL
{{base_url}}/tasks (same Prefer header)
Body
{"title":"Finish the API lecture","user_id":"PASTE THE USER ID"}
Expect
201 + the row. Copy the task's id (not the user's).
Try
Body {"title":"x"} with no user_id: 400 "null value in column user_id". The database's rule, passed back by the API.

GET Read the tasks that aren't done

URL
{{base_url}}/tasks?is_complete=eq.false
Body
none
Expect
200 + a list with your task. eq means equals: the filter lives in the URL.

PATCH Tick the task off

URL
{{base_url}}/tasks?id=eq.PASTE THE TASK ID
Body
{"is_complete":true}
Expect
204 (done, nothing to send back). Send the GET above again: the task is gone from the "not done" list.

DELETE Delete the task

URL
{{base_url}}/tasks?id=eq.PASTE THE TASK ID
Body
none
Expect
204. Check the Table Editor: the task is gone. Leave the user.
Careful
204 also comes back when nothing matched (wrong id). To be sure, add Prefer:return=representation: you get the deleted row back, or [] if nothing was deleted. Always filter a PATCH and a DELETE: without ?id=eq. it would hit every row.

5 · Break it on purpose

  1. Change one letter of publishable_key → 401 "Invalid API key". Change it back.
  2. Request {{base_url}}/taks (typo) → 404.

Import the ready-made collection

The same 7 requests, already built. Good as a check against yours, or as a backup.

  1. Get the collection: Download Ticked-API.postman_collection.json
    or copy the JSON from the box below.
  2. Postman → Import (top left). Drag the file in, or paste the copied JSON into the box.
  3. Click the new Ticked API (Supabase) collection → Variables. Fill in base_url (ending in /rest/v1) and publishable_key. Save.
  4. Run the requests in their numbered order. After 2. Create a user, copy the new id into the user_id variable. After 3. Create a task, copy its id into task_id. Save each time. Requests 6 and 7 use {{task_id}}.
